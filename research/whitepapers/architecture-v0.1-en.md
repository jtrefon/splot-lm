# SPLOT: A hardware-aware recurrent sparse predictive language model
Architecture whitepaper — working draft v0.1, 2026-11-26. Independent open research; no institutional affiliation, no empirical claims. [Polski](architecture-v0.1-pl.md).

## Abstract
We propose a modular decoder-only architecture that combines shared recurrent depth, hybrid gated delta and grouped-query attention, sparse mixture-of-experts and native multi-token prediction. SPLOT tests whether these mechanisms jointly improve the quality–computation–memory trade-off on commodity hardware. Rather than assume that sparse routing, recurrence or speculative decoding necessarily deliver acceleration, we specify controlled comparisons and exact causal verification. The design targets 43.06M and 146.99M physical parameter research variants; these counts are analytical and independently validated against a meta-tensor inventory, not trained-model results. The present draft describes hypotheses and a validation plan, not a completed experimental paper.

## Motivation and contribution under investigation
Recurrent depth reuses parameters but repeats compute and may require separate activation states. Hybrid attention trades growing KV memory for fixed associative state without removing quadratic prefill in remaining full-attention layers. Sparse experts increase physical capacity while only a subset execute at each pass; route diversity and expert transfer costs can conflict. Native MTP may enable useful intermediate readouts, yet extra training projections and rollback can consume the expected savings. The research question is whether these trade-offs can be improved together under fixed hardware and quality constraints. Prior art includes GDN, GQA, Huginn, Ouro, LOOM, LoopMTP, LoopSpec, Floodgates, DuoMI and cache-aware MoE methods. No claim that any one ingredient, or their combination, is novel without wider prior-art review.

## Architecture and methods
The precise contract is [RFC 0001 v0.2](../rfcs/0001-architecture/contract-v0.2.md). Eight physical blocks: two dense GQA prelude, four shared hybrid MoE core (3 GDN + 1 gated GQA), two dense GQA coda; fixed 1–4 passes, tied embeddings and shared offset-2 MTP projection. Recurrent functions are invariant to requested depth within immutable config, enabling prefix-compatible shallow computations; coda states and each logical mixer invocation remain distinct. Exact verification uses conditional proposal probabilities and snapshot/replay of rejected suffixes; the target distribution is not modified by cache policy. Separate cache-only and retrained routing experiments. Dense all-GQA, dense recurrent, hybrid-only, MoE-only and NTP/MTP controls isolate interventions.

## Evaluation
Register token budget, matched parameter/compute comparisons, dataset lineage, tokenizer, split, seeds and hardware before training. Measure held-out loss, reasoning and code tasks, retrieval, intermediate depth benefit, active expert union/diversity, prefill/decode latency, cache and peak allocated VRAM, bytes transferred, acceptance and rollback. Do not conflate analytical MACs or persistent state bytes with actual performance. Pilot Nano, then Mini on RTX 4090 only after correctness and budget gates. Report negative results and uncertainty; broader-scale conclusions require replication.

## Evidence and limitations
Five toy recurrent scheduling and six hybrid equation tests are documented in merged RFCs; six new accounting checks validate this contract's inventory. None is an end-to-end model result. Data provenance, implementation, precision policy, exact stochastic verification, optimized GPU kernels and empirical comparisons remain open. Vision/audio, adaptive token depth, low-bit training and offloaded large models deferred.
