## 1. Bilingual pretraining strategy
English and Polish are first-class languages, not translation-only or a 5% multilingual afterthought. Target mixture is by realized non-padding content tokens after the frozen tokenizer (exclude BOS/EOS for quota accounting; report them separately). Each document assigned to one mutually exclusive bucket; code/math selected before educational/general and reference so quotas do not double count.
| Bucket | % | 100M-token pilot | 1B-token pilot |
|---|---:|---:|---:|
| English educational/general high-quality prose | 30 | 30M | 300M |
| Polish educational/general high-quality prose | 30 | 30M | 300M |
| Code, with verified source rights | 20 | 20M | 200M |
| Mathematics/reasoning, EN/PL | 10 | 10M | 100M |
| Reference/technical prose, EN/PL | 10 | 10M | 100M |

For the last two buckets aim at half Polish content tokens, where quality and rights allow; code is a separate domain, track language of comments where reliable. Thus natural-language content target is ~40% PL, 40% EN, plus 20% code; actual proportions reported, not guaranteed. Compare 70:30 vs 50:50 EN/PL within natural language at equal content-token budget on the same held-out sets. This is a proposed pilot, not a scaling law or claim that balanced sampling is optimal. Avoid oversampling a tiny Polish subset excessively; report unique tokens/documents, repeats, domain and language distribution. Begin with 100M tokens only once license/quality/cost gates pass; Nano first. 1B is a future scale, not downloaded. Do not replace a blocked bucket silently or include unlicensed sources to meet a quota; preregister revised mixture. English and Polish test suites should measure each independently; report both macro and token-weighted metrics.

## 2. Source rights and provenance
See [versioned source registry](sources-v0.1.json). Source licenses stated by upstream are NOT independent clearance of the underlying content. FineWeb-Edu and FineWeb-2 declare ODC-BY 1.0 database licensing and Common Crawl conditions; individual source material may remain copyrighted. Use URL/domain filtering, machine-readable rights signals, opt-outs and jurisdiction-appropriate legal review (including EU TDM reservations where applicable); never bypass paywalls/access controls. No presumption that commercial or redistribution rights follow from database license or training eligibility. Wikipedia has attribution/share-alike requirements and page-level exceptions; Wolne Lektury is useful but item-level rights, edition/annotations and attribution matter. The Stack v2 contains permissively licensed and undetected-license files; only allow explicitly verified license IDs such as MIT/BSD/Apache-2.0 after file/repo lineage and attribution review; reject missing, ambiguous, conflicting licenses and opted-out files. Do not accept gated terms without maintainer approval. Start with own cleared original material and public-domain or explicitly licensed sources; web sources are candidates only. Weights/tokenizer/processed-data redistribution decisions are separate, with #11 and qualified rights review. No external data committed to Git.

Before acquisition pin dataset revision (immutable commit or dated dump URL + checksum), subset, file hashes, source license version and date, terms/opt-out evidence, review status, attribution and access route. For each document keep stable source ID and revision, original URL or repository commit/path, content SHA-256, source group ID, language+confidence, domain, timestamp where available, license evidence reference, retrieval date, preprocessing version, exact and near-duplicate cluster, split, exclusion reason. Raw URL/PII kept in restricted manifests when necessary; publish aggregated stats/hashes and lawful provenance only. A null revision/rights decision blocks acquisition for training. Manifest version refers to registry, not to an approved immutable corpus. Maintain removal/rebuild procedure and track impacted artifacts. Explicit source rights and data protection review required before training or publication.

## 3. Deterministic acquisition, split and contamination
1. Freeze approved source list and versions, extract exact text with original whitespace/diacritics/code indentation. Reject invalid UTF-8, secrets/API keys, PII beyond intended use, malware payloads, boilerplate, duplicate mirrors, spam and policy/rights exclusions. Do not silently normalize model input. Log aggregate rejection counts, review samples per language.
2. Before any split, build globally connected components over source-family IDs (same article/revision chain, translated pairs, code fork/repo families, same book/edition), exact text hashes, conservative NFC/line-ending dedup fingerprints, near-duplicates (proposed 5-word shingles MinHash candidate retrieval, verify exact Jaccard >=0.8, calibrate for Polish morphology/code separately). Include overlap between sources and across domains. Cluster first, then choose stable canonical representative; retain lineage of all removed duplicates. Do not infer semantic equivalence solely from hash. For code use repository/fork graph and token shingles; near-duplicate thresholds need audit. Near-duplicate transitive giant clusters can be quarantined rather than split.
3. Establish benchmark exclusion list before corpus or tokenizer training (EN/PL reasoning, code, math, retrieval; confirm licenses and version IDs before processing). Search exact/normalized question and solution overlap, long n-grams, code signatures, translated/paraphrased variants and known benchmark repo families; quarantine hits and suspected cluster members. Report coverage, false positives, residual risk and benchmark version. This cannot prove absence of contamination. Keep final benchmark untouched; use validation for tuning.
4. Freeze split manifest by stable group/cluster IDs with seeded hash, target 98/1/1 for real large pilot (fixture uses 80/10/10); allocate by cluster, audit language/domain token counts and minimum holdout size. Reserve explicit group/domain/time holdouts for robustness separately. Stable hash assignment depends on frozen cluster membership; if dedup groups change, create new dataset revision, don't silently alter split. Zero shared exact hashes and cluster IDs across splits is mandatory; near-duplicate audit after split required. Tokenizer trained ONLY on train documents. Never shuffle individual tokens into validation.
5. Tokenize with fixed artifact/hash, sample deterministically by token budget, record order/shard manifest, pack within split. For production long documents split into explicit segments within original document's assigned split; preserve parent ID/offset; start with disjoint segments and record dropped boundary labels/context, no hidden truncation. Pack with BOS/EOS; position resets at each segment, padding no state update, no attention across document IDs, NTP/MTP masks exclude cross-segment labels. Validate no repeated evaluation segments in training. Export manifest of token counts, unique docs and clusters, hashes, train/validation/test proportions, near-duplicate audit, source attribution and code revision. Real data pipeline remains to implement.

## 4. Tokenizer choice
Proposed **shared byte-level BPE**, vocabulary capacity 32768, trained from scratch on approved train-only data. Compare 16K and 32K and a pinned existing tokenizer as an analytical/evaluation comparator if license permits. Byte-level mapping uses all 256 byte symbols as initial alphabet, no lossy normalization, preserve whitespace/indentation/diacritics, no artificial prefix space, deterministic pretokenization (HF Tokenizers ByteLevel regex initially), byte-level decoder, special tokens reserved before merges. Pin tokenizer library/version, single-thread training if needed for reproducibility; log ordered sampled docs/hashes, seed/order, pretokenizer and configuration, output tokenizer.json SHA-256, actual vocabulary size and token ID map. No requirement that a tiny sample fills capacity: fail production build if vocab not exactly 32768 or revise model config explicitly. No tokenizer trained here. Initial tokenizer sampling by UTF-8 bytes to avoid circular dependence on token counts: 40% Polish, 40% English natural-language, 20% code, including math and technical material in each language. Proposed 50–100 MB unique training sample (not measured optimum), deterministic within approved data, no val/test. BPE candidate selection on held-out validation fertility/bytes per token across EN/PL/code/math; report p50/p95, unknown/control-token rates, exact Unicode round trips (Polish inflections, diacritics, combining sequences, emoji, indentation, LaTeX), compression, throughput, and English/Polish bits per byte for LM comparisons across tokenizers. Report fertility by language; don't compare perplexity alone across tokenizers. Proposed target: PL median tokens/word no more than 1.3x EN on matched prose samples, and neither domain regression >10% vs chosen pinned comparator; both thresholds provisional, not guaranteed; compare byte counts too. No special token interpretation in untrusted raw text: tokenizer wrapper must treat reserved spellings as ordinary text or reject explicitly and log, no accidental EOS injection. Reserved IDs: PAD=0, BOS=1, EOS=2, UNK=3, 4–7 reserved (future controls, no current semantic meaning). UNK should never occur on valid Unicode with complete byte alphabet. Padding/control IDs never generated as raw text. BOS/EOS appended by packer, not tokenizer. Decoder round trip excludes explicitly inserted control tokens. Fixture raw bytes IDs 8–263 are only a fixture mapping, NOT promised BPE byte IDs. No actual production special token strings chosen except proposal in config.

## 5. Executable contract for model baseline #9
[tools/data_fixture.py](../../tools/data_fixture.py) implements dependency-free UTF-8 byte codec, conservative exact dedup+union before deterministic splitting, whole-document packing, and reproducible synthetic manifest. It rejects oversized documents rather than silently clipping. Data returned per block: input_ids [T] int, document_ids [T] int (padding -1), position_ids [T] int (reset), valid [T] bool, labels mapping offset -> [T] int (ignore -100). Offset k label is token t+k only when same segment and valid; no cross-document prediction, EOS learnable, no label for EOS crossing, pad ignored. Batch tensors [B,T]; GQA causal mask same valid segment, GDN reset when segment changes and no update on padding. #9 may implement and test with this fixture independently of production corpus. Synthetic smoke tests may run with 264-token toy vocabulary or 32768 candidate capacity (record which; not real tokenizer). Do not use fixture for claims of generalization, quality, tokenizer fertility or semantic contamination; templated examples intentionally repeat topics across splits. Exact dedup and group isolation are tested, near-duplicate and benchmark decontamination are NOT implemented in the fixture.
