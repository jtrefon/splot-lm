# Corpus portability and physical storage
2026-11-27 | Proposed operating decision, #8 / #38
One GitHub repository is the canonical recipe and evidence store, not a dataset server. Mac develops/tests code on bounded original synthetic fixtures; Linux materializes approved production corpus and owns training checkpoint storage. No assumption of shared filesystem, network reachability, account or cloud budget. T0004 scope unchanged. No new data access or transfers authorized here.

## Dataset release identity
Freeze source IDs, immutable revisions and upstream checksums, rights decision/attribution references, acquisition/filter/normalization/dedup/split code SHA and dependency lock, configuration, seed, deterministic input order and representative selection, tokenizer SHA and content token budgets. Record stable doc/cluster IDs, split and provenance in appropriate restricted manifest; publish only lawful aggregates/hashes and safe artifact references. Distinguish logical identity from physical representation: canonical ordered records with unambiguous length framing or canonical JSON UTF-8 lines and SHA-256; physical per-shard relative path, bytes, SHA-256, record/token counts and format/version. Do not assume compressed or Parquet bytes deterministic across platforms. If logical identity agrees but physical bytes differ, register new physical artifact manifest; never silently reuse old byte hash. Pin dependency versions and compare small deterministic fixture on both platforms. Full manifests may be large/private; publish root digest, summary and approved location rather than raw private URLs or entire corpus.

## Local materialization and transfer
Default: Linux reproduces approved corpus using same pipeline and pinned sources; retain verified immutable raw snapshots when licensing permits because remote availability may change. Use machine-local data root (explicit config/env, not absolute Mac paths committed to Git) outside checkout. Staging then verify manifest/hash/counts and atomic promotion; read-only frozen dataset revision during runs. Never train against incomplete or changed shards. Cache independently if needed. If rebuild too costly, owner may authorize one-way transfer of approved immutable artifacts via existing SSH/rsync on trusted network or external encrypted SSD. No new network exposure/daemon or shared live mutable directory. Verify source/destination SHA-256 and completeness; no deletion sync, no overwrite of existing releases, preserve source until verified. Private object storage only when justified, licensed and separately approved; no public raw corpora, checkpoints, or credentials. Tokenizer artifacts may travel via Git only if small, rights-approved and safe; otherwise digest/reference. All checkpoint tensors stay local unless explicitly authorized. No transfer, storage service or data acquisition performed by this decision.
