# RFC 0008 — Quantization-aware pretraining and precision allocation
2026-11-28 | proposed, not adopted | #126, parent #7, #85/#6/#87/#2/#42
## Motivation and evidence
Native FP8 execution remains on scan path (T0007/T0017/T0020). T0020 reuse-disabled FP8 slower than BF16 in synthetic updates; T0017 real pilot feasible; no blanket rejection. T0025 BF16 chunk64 rejected, T0033 FP32 chunk64 qualified. These are distinct from learning deployable low-bit weights. Fake quantization may increase training overhead and does not reduce master weights, gradients or optimizer storage automatically. Ada RTX4090 supports native FP8, not native NVFP4; Blackwell study is future hardware-specific work. No native INT4 training claim.
References: BitNet b1.58 2B4T https://arxiv.org/abs/2504.12285 (ternary-from-scratch precedent); ParetoQ https://arxiv.org/abs/2502.02631 (budget allocation/quantizer choices; late ~10% in studied settings, not universal); Compute-Optimal QAT https://arxiv.org/abs/2509.22935 (cooldown fusion, scale-dependent allocation); Scaling Law for QAT https://arxiv.org/abs/2505.14302 (group size, tokens, model size); Mixed Precision Scaling Laws for Quantized Pretraining https://arxiv.org/abs/2610.17637 (preprint; per-layer forward/backward precision); NVIDIA hardware matrix https://docs.nvidia.com/deeplearning/transformer-engine/support_matrix.html. Prior art, no novelty assertion.
## Proposed research sequence
1. Establish T0035 matched FP32 scan/chunk and dense reference learning on existing corpus. Maintain BF16 and native FP8 scan independently, no combination with chunk64 yet.
2. Implement isolated deterministic weight-only W4A32 fake quantizer on FP32 chunk64 after review. Initial candidate symmetric signed INT4 codes [-7,7] (15 levels, -8 unused), group size 64 along input axis per output row, scale max(abs(w))/7, zero group scale explicit positive convention, nearest-even round/clamp, FP32 scale and master weights, straight-through gradient for weights (explicit detach scale, identity STE), forward dequantized FP32 GEMM, no low-bit GEMM assertion. Test exact quant/dequant, padding tails, zero group, deterministic rounding, gradients/optimizer/resume, parameter alias/tied embedding integrity, finite scales/NaN rejection, packed serialization independent decode and equivalence to fake-quantized forward. Compare with W8 same scheme only as a separate control. No new kernels/packages by default. Quantize physical routed-expert gate/up/down matrices first; shared experts/dense MLP separate subsequent ablation. Leave router, recurrent gates/state, norm, embeddings/tied head, GQA, MTP and activations FP32 initially. Shared physical weight quantization must be consistent across logical passes, not duplicate parameters; no persistent stale dequant cache across optimizer updates. Do not train recurrent matrix state in INT4. FP8 native kernels unchanged.
3. After implementation correctness, prospective learning arms with identical base architecture, seed/order, optimizer and total token budget: Q0 unquantized then same-format PTQ; Q1 W4 fake quant from start; Q2 unquantized warmup then W4 for last 10% of updates (rounding rule fixed), optional Q3 last 20% only with additional budget. Same LR schedule across arms initially (cooldown fusion a separately controlled comparison). Evaluate all on identical deployed W4 representation, unquantized baseline and master-weight context separately. Dense comparator with matched quantized parameter fraction and policy, both physical budget and measured packed size including scale overhead; do not pretend expert-only and full dense W4 are equal. Larger corpus and held validation families required before confirmatory study; tiny pilot only feasibility. Three paired seeds exploratory, power/margins separately reviewed before larger runs. 
4. Examine quantization noise by logical depth, local same-input contraction vs propagated error, router top2/3 margins, route changes, load/entropy/dead experts, NTP/MTP loss separately, weight saturation/rounding error, gradient norms and finite checks, packed weight footprint, measured train cost, deployed TTFT/committed t/s and tier traffic. Natural routing under QAT may change; exact cross-precision routing is not a learning criterion, but same quantized representation implementation must reproduce its own routes/outputs within prespecified numerical contract. No forced routes for acceptance. Quality vs PTQ at equal token budget and actual deployed cost is core outcome; no guarantee of QAT superiority. Freeze test until protocol fixed. No claim training memory saving from fake quantization.
## Candidate deployment math
Ideal selected W4 group64 with FP32 scale costs 4 + 32/64 =4.5 bits/weight before metadata/padding, not 4 bits exactly; relative to FP32 selected weights ~7.11x, BF16 ~3.56x, not entire model. If fraction f selected, ideal mixed BF16 bits/weight =16(1-f)+4.5f, FP32 analogous. Actual packed artifact and resident memory measured. Expert offloading #6 can later consume packed physical expert weights without changing routing; quantization error distinct from exact residency. No new training or implementation authorized by RFC; after T0035, review bounded QAT task.
