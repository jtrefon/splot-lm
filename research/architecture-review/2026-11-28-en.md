# SPLOT architecture decision review — 2026-11-28
Status: **proposed v0.3 research direction; not accepted model changes or an empirical SPLOT paper**. Issue [#85](https://github.com/jtrefon/splot-lm/issues/85). Inspected main `6e8911662ac56df665147cb79e412f0383cf71d8`. [Polski](2026-11-28-pl.md). [Source register](sources.md).

## Decision in brief
Conditional GO: preserve the validated v0.2 baseline and finish T0017/T0018 unchanged. Do not commit to expensive sustained pretraining or Mini until the next architecture gates are reviewed. The architectural premise is credible, but the current implementation is not yet a differentiated desktop inference architecture. Promote conditional memory and heterogeneous residency to first-class research candidates; evaluate recurrent stability, partial weight untying and fine-grained sparsity before freezing v0.3. Prefer measured, single-variable changes over an unidentifiable collection of trendy components.

## Current actual implementation, not aspirational claims
- `src/splot/recurrent.py`, `sparse.py`, `gdn.py`, `dense.py`, `moe.py`, `mtp.py`: 2 GQA prelude + 4 shared hybrid sparse core (3 GDN, 1 gated GQA) + 2 GQA coda. Fixed 1–4 passes; 8 routed experts top-2 + 1 always-active shared expert per core pool. Shared routers/mixers across passes; optional additive/convex input injection, depth embeddings and residual scaling already exist, default pilot I0/S0 (none/unscaled), no depth embeddings. GDN state/cache logically separate across passes; explicit per-token scan reference. Full GQA has explicit score/softmax materialization. MoE uses stable full argsort and per-expert nonzero/gather/index_add, not grouped device kernels. Physical Nano 43,055,076, Mini 146,987,784 at V32768. Mini sustained CUDA unqualified.
- Native FP8 selected projection training E4M3/E5M2, FP32 masters/wgrad/optimizer and sensitive states; Muon+AdamW; per-step weight quantization reuse. [T0017 attempt-001](../../experiments/results/T0017/attempt-001/summary.md) T512 matched exact post-update states and 298→156 actual quantizations, 1.949→1.633s one pair; not persistent inference quantization or residency.
- `speculative.py`: exact D1 serial shallow drafts, D2 independent offset-2 proposals, CPU float64 sampling, independent shallow/target prefills and replay. Not optimized and not yet benchmarked on real-trained weights. T0018 instrumentation outstanding.
- **No learned n-gram memory, no host/SSD expert provider, no quantized expert file format, no runtime cache scheduling, no latent MoE, no sparse token indexer, no adaptive depth**. RFC 0004 contains a locality proposal, not implementation. FP8 per-update weight reuse is not equivalent to inference expert residency.
- [T0012](../../experiments/results/T0012/attempt-001/context-summary.json) Nano R2 B1 T4096 FP8/Muon peak reserved 15,699,279,872 B (14.62 GiB), 10.1358s update; BF16 16,007,561,216 B (14.91 GiB), 9.8039s. Single case per precision, reference overhead. [T0009](../../experiments/results/T0009/attempt-002/summary.md) Nano R4 full gradient relative L2 drift .342295 vs BF16, no trained stability conclusion. [T0016](../../experiments/results/T0016/attempt-001/summary.md) real 16k BPE and 56,201 selected content tokens, model V32768. T0017 real training not run; exact continuation pending. 64-step pilot is a sanity checkpoint only, not evidence for language competence or conditional-memory quality.

## Comparative evidence and risk
Selected primary sources, as of review date; not a systematic review, no independent replication of external results.
- Qwen3.8-Flash-Next, [report §2–3](https://arxiv.org/html/2608.30320v1) and [model card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next): 125B backbone, 6B active, 51B n-gram tables outside accelerator plus 4B MTP; 512 routed experts top-10 + shared, hybrid 3:1 GDN/QSA, gated residual, hybrid optimizer. QSA introduced during continued pretraining, not obligatory from scratch. This is the closest conditional-capacity comparator, not a direct Nano benchmark.
- Thinking Machines [Inkling 2 Mini, 20 Nov](https://thinkingmachines.ai/news/inkling-2-mini/): 26.4B/5.4B active, 24 stored layers, middle 12 repeated three times (48 logical layer applications); prelude and learned gated message from prior pass, block attention residuals; expert pruning and low-bit Blackwell training. Supports sandwich/recurrent research, not SPLOT novelty or Ada NVFP4 training.
- [GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash) 320B/18B active, hybrid sparse/linear attention and mHC. [GLM-4.7-Flash](https://huggingface.co/zai-org/GLM-4.7-Flash) 30B/3B active. "Flash" is a model variant name, not a storage backend. Actual offload needs an inference engine.
- [DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash), [report metadata](https://arxiv.org/abs/2609.19969): 552B backbone + 196B Engram, causal encoder–decoder, compressed sparse attention, single-pass mHC and DSpark; distinct prefill/decode active counts. Not comparable as a desktop benchmark.
- [Engram, Jan 12](https://arxiv.org/html/2601.07372v1), §§2.2–2.5, 3: multi-head hashed n-gram rows, context gate, deterministic prefetch and capacity allocation between memory and MoE. Their host-memory result does not prove random NVMe reads are negligible. [vLLM Engram](https://docs.vllm.ai/en/stable/features/engram/) illustrates pinned host/UVA implementation.
- [LOOM](https://arxiv.org/html/2610.01153v1) §§3–4: residual scaling, re-injection, loop-specific routers and loop residuals. [Foil](https://arxiv.org/html/2609.35751v1) §§2–4: fewer expert pools with more experts per pool and more passes at matched expert compute/capacity, separate attention weights per pass. [MoRE](https://arxiv.org/abs/2609.18176) and [Meta Expert](https://arxiv.org/abs/2610.27598) abstract-level cross-layer shared pools. [Sparse Layers](https://arxiv.org/abs/2605.09165) abstract emphasizes routing divergence. Full-block sharing is a control, not proven optimum.
- [DuoMI](https://arxiv.org/abs/2611.33952), 25 Nov: dual information regularization for aggregate reuse and bounded token-level changes. [Cacheable by Design?](https://arxiv.org/abs/2608.18261) reports negative preregistered locality result at <=1% PPL-loss gate despite reduced cache misses. Do not reward maximal overlap or claim locality objective alone novel.
- [Floodgates](https://arxiv.org/abs/2611.33896), 25 Nov: shallow masked suffix parallel proposals conditioned on verified deep prefix; author-reported up to 7.5x on evaluated looped models. [LoopSpec](https://arxiv.org/abs/2609.17184): pipelined shallow proposals; [LoopMTP](https://arxiv.org/abs/2608.03624): latent future embedding supervision and gated recurrence. [Nemotron 3.5](https://research.nvidia.com/labs/nemotron/Nemotron-3.5-Super-and-Lightning/), Oct 14, native MTP post-training improves deeper draft positions. None establishes SPLOT acceptance rates.
- [LatentMoE](https://arxiv.org/abs/2601.18089) and [NVIDIA technical explanation](https://research.nvidia.com/labs/nemotron/LatentMoE/): low-dimensional routed expert space can change compute/byte tradeoffs. Candidate after basic granularity and residency, not default.
- [Strata](https://strata.amperor.ai/docs/), [HF expert-streaming engineering report](https://huggingface.co/blog/moe-expert-streaming), [SSD-LLaMA](https://arxiv.org/abs/2609.18110), [FlashMoE](https://arxiv.org/abs/2601.17063): storage tiers, expert caches and CPU/GPU execution are existing systems research. HF blog reports Qwen3.8-Flash-Next on 32 GB M5 with SSD-backed experts AND n-gram rows, 13.9 tok/s vs Strata 14.8 in its short greedy decode workload; quantized, no MTP, hardware/prompt specific, not independently verified. SSD-LLaMA reports >1 tok/s for trillion-parameter MoE on RTX5090 + <=32GB RAM. Do not claim SPLOT first or faster.
- [FlashAttention](https://arxiv.org/abs/2205.14135), [Cut Cross-Entropy](https://arxiv.org/abs/2411.09009), [GDN official repo](https://github.com/NVlabs/GatedDeltaNet), [cuDNN linear attention](https://docs.nvidia.com/cudnn/latest/operations/LinearAttention): mature mechanisms for eliminating avoidable materialization, but exact version/hardware/gradient support must be qualified on existing Ada environment. [GDN-2](https://arxiv.org/abs/2605.22791) decoupled erase/write (abstract). [Muon](https://arxiv.org/abs/2502.16982): scaling evidence with weight decay/update scaling, not evidence our zero-decay smoke LR is optimal.

## Candidate A: causal conditional memory (#86)
Separate learned static knowledge from dynamic conditional compute. Proposed baseline-compatible optional module: one early insertion after first prelude block or after prelude; n=2,3 independent heads (start 4/order), bounded deterministic integer hash over current and preceding in-document token IDs with explicit start sentinels, no future IDs/padding access. Separate row tables; raw tokenizer IDs first, optional compression separately evaluated (avoid folding Polish diacritics/case/whitespace by default). Memory vector e_t concatenates rows; project to model d; gated residual z'=z+g(h,e)*Wv e with small nonzero initialized gain or one zero-initialized branch, not dead double-zero gates. FP32 sensitive gate, dense projections qualify precision later. Shared static e_t and projection may be reused per pass; **context-dependent gate/output cannot be reused across changed hidden states**. Option A0 no table, A1 early one-time memory, A2 re-gate same retrieved vector at each pass. No RAG or external document database. Ensure full vs incremental and packed doc isolation, gradients touched rows only where supported, hash collisions measured, checkpoint identities, exact speculative replay including n-gram prefix history, data train-only.
Illustrative table 2 orders ×4 heads ×16,384 rows ×32 dims =4,194,304 parameters excluding projections/gate. INT8 payload 4 MiB; 8 row lookups ×32 B =256 B/token logical (scales/metadata excluded), worst-case independent cold 4 KiB pages =32 KiB/token. Larger 2^16 rows/head =16,777,216 parameters/16 MiB INT8. These are toy geometry choices, not quality or I/O predictions. Compare extra table capacity vs extra experts, and iso-total allocation (reduce expert capacity to fund table while keeping routed compute and shared expert comparable). Account projections and optimizer states; do not hide table parameters outside total. For Nano/Mini fit all resident first. Table learning requires sufficient distinct n-grams/row coverage; 56k-token pilot cannot evaluate a large table. Row optimizer separate from matrix Muon; dense AdamW on small tables as reference, sparse/lazy optimizer must explicitly define untouched-row decay/moments and exact resume. SSD-backed large-scale training is out of scope; inference uses immutable exported rows only. Evaluate unique row coverage/collisions/frequency, NLL/bits per byte per language, rare and common n-grams, retrieval and reasoning; size/placement sweep, no fixed Engram ratio assumed.

## Candidate B: heterogeneous residency contract (#6)
Design checkpoint-level immutable parameter provider decoupled from execution. Keys (checkpoint, physical expert/pool, quant format/layout), **no pass ID** for shared weight. Separate logical KV/GDN/prefix caches by pass and sequence; do not evict in-flight buffers. VRAM holds dense/shared weights if feasible, active expert slots, state and scratch; DRAM holds warm expert pages and memory rows; SSD cold aligned expert chunks and tables. UMA Mac uses unified memory budget instead of PCIe. CPU expert execution transfers activations, not full weights; compare with GPU load-and-run using same quantized representation; alternative CPU/GPU kernels need declared numerical tolerances. Cold exact miss loads selected expert or blocks; predicted prefetch can never replace router selection, no dropping/renormalization. Deterministic n-gram address prefetch distinct from probabilistic expert hints. Keep expert/row page caches separate; speculative discarded drafts can pollute immutable caches, measure. Store per-expert format/scales/hash/offset/alignment; bounded slot pools and async copy/read with backpressure; no training from paged weights at this gate.
Trace from actual decode chronological (not training layer-major), include token position, phase, pass/pool, selected IDs, load/evict/prefetch, byte counts at each tier, page/read amplification, hit rate weighted by bytes, latency p50/p95/p99, TTFT, committed t/s, cold/warm, false prefetch, wasted draft traffic, device peak/host RSS/disk/energy. Test all-resident same quantized checkpoint, equal-budget static/LRU/LFU, causal cross-pass/draft predictor, offline oracle; forced offload on Nano proves scheduler semantics, not large-model performance. Measure device link, random IOPS and transfer bandwidth on actual desktop before target; compare actual selected expert outputs and greedy tokens, sampled distribution tolerance; quality effect of PTQ separate from scheduling.
Bandwidth illustration only: hypothetical 12 pools, 512 experts/pool, d4096,m1024, k4,R3, int4 packed payload excluding scales. Routed experts 77.31B params /38.65 GB; 144 expert invocations/token, 905.97 MB if all miss/no dedup. With 4 GB/s effective SSD payload bandwidth, cold optimistic ceiling 4.42 t/s before any compute; at 20 t/s need >=77.9% of cold bytes avoided, 40 t/s >=89.0%. At 24 GB/s effective PCIe, cold copy ceiling 26.5 t/s (same assumptions). Physical reuse across passes can reduce miss bytes but not repeated matmuls; SSD random I/O, pages, cache eviction, latency, scales, CPU/attention/compute lower bound. Formula: tokens/s <= min_j(BW_j / bytes_per_committed_token_j) and compute bound; latency/overlap impose further constraints. No promise of 100B-class training or inference speed.
Hypothesis: recurrence-aware caching plus deterministic memory prefetch improves bandwidth/quality frontier vs same-budget LRU; compare cache-only exact phase first. Only then train bounded locality band / DuoMI controls, not maximum overlap. Preserve RFC0004 proposed >10% fewer transferred bytes AND >10% net decode speedup on fixed checkpoint with equivalent output; for retrained candidates <=1% relative PPL degradation plus downstream/depth checks, preregister before confirmatory results. If no improvement, retain exact baseline and report negative.

## Candidate C: recurrence/topology and sparsity (#87)
Current routed fractions E8/k2=25% (not total active ratio), shared + routed 3/9 FFNs executed per pool. Per expert 3dm, routed storage Nano 18,874,368 params (43.84% total), Mini 75,497,472 (51.36%). Remaining nonrouted incl auxiliary Nano 24,180,708, Mini 71,490,312. For same width, k2, E32 increases total incl router to Nano 99,715,044 / Mini 373,553,928; more storage, approximately same routed contractions but router cost changes. E32/k4 half expert width, keep shared expert width separate, yields Nano 61,966,308 / Mini 222,558,984 incl router; same k*m and shared FFN compute, increased router/dispatch and total storage. Not an iso-total comparison; design a matched additional control. Do not conflate active unique physical params across R passes with executed FLOPs. More passes can activate all 8 experts eventually.
Partial untying: all core mixer params Nano 2,780,388; Mini 11,093,256; R4 separate copies add 8,341,164 /33,279,768 (19.37%/22.64% total, excluding norms/router changes); could unlock more expressivity with expert reuse. Candidate R0 full sharing baseline, R1 existing scaled residual + additive/convex injection, R2 learned bounded loop-message gate (prelude anchor, pass index independent of requested final R), R3 depth-conditioned/router bias or independent per-pass router, R4 untie gated GQA only then all mixers if justified, R5 shared/flattened expert pools across physical blocks, separate logical state. No wholesale copying all variants; ablate sequentially, quantify capacity and executed cost, preserve prefix-compatible function for fixed Rcap. Later dynamic per-token halting requires new causal state policy (cannot skip required state updates). 
Record per-pass RMS/gradient norms/cosines, quantization drift, delta loss/depth gain, routing entropy, margin, cross-pass/time overlap vs marginals, expert union/reuse, dead expert fraction, heldout depth quality, route diversity and gradient coverage. Use matched R1/2/4 training and test; avoid claim more loops = intelligence. Loss scale stability and final quality are separate. Test controlled learned gate before expensive mHC/block residuals; consider wider residual only after resource evidence. Foil and LOOM use distinct architectures, not drop-in proof for hybrid GDN.

## Candidate D: execution, context and MTP (#7/#10/#2)
Priority after current pilot: profile first, optimize exact reference before changing attention semantics. GDN scan unroll saves intermediates, GQA explicit attention, multiple full-vocab outputs and audit overhead. At Nano B1,T4096,V32768 a single BF16 logit matrix =256 MiB; A2 R2 can emit 2 NTP+2 offset heads (1 GiB BF16 payload if co-resident, 2 GiB FP32; not measured allocation). Six GQA score tensors at 6 heads, FP32, T4096 each 384 MiB if materialized; scan full FP32 state at every token also 384 MiB per GDN call if materialized. Do not sum as measured peak. Separate kernels/timing/activation allocations. SDPA/FlashAttention mask and GQA semantics, chunked GDN with FP32 recurrence and packed boundaries, checkpoint/recompute, exact tiled vocabulary CE (approximate gradient cutoff separate), grouped expert dispatch, fused GPU scaling/quantization with preserved finite guards. Runtime support pinned, no dependency upgrade without owner. Keep explicit reference paths and test forward/backward/resume; performance measured after warmup/repeated paired cases. 
Model V32768 vs actual tokenizer16384 means 16384 unused output classes in pilot; preserve pilot unchanged but next matched training config should use actual vocabulary, reducing Nano tied embedding by 6,291,456 params (Nano 36,763,620 before other changes), and Mini by12,582,912 (134,404,872). Report counts; not mask unused logits silently or compare different normalizers as same model. 
GQA fraction for final inference R1=5/8, R2=6/12, R4=8/20 (not 25% global). BF16 KV Nano 3072 B/token R2, 4096 B/token R4; Mini 6144/8192. At 262144 tokens R4 KV alone Nano 1 GiB, Mini 2 GiB; plus GDN state, other memory, metadata. Later consider windowed/sparse global attention, compressed KV and GDN-2/KDA only after exact optimizations/long-context accuracy. No 1M context claim. 
T0018 instrument D0/D1/D2. Then same trained checkpoint and prompt sets, greedy equality and stochastic distribution separate, proposal examined/proposed denominators per offset, committed t/s incl replay/bonus/TTFT, phase and byte metrics. D1/D2 duplicate shallow/target prefills and replay currently; a naive speedup claim is invalid. Explore Floodgates D3 parallel suffix (deep prefix cache read), LoopSpec D4 pipeline, LoopMTP latent objective and conditional/sequential MTP as independent variants. Deep GQA KV reuse may be possible; GDN associative state is not token-addressable KV and shallow/deep states are not interchangeable. Require explicit causal state/rollback rules and exact verifier using actual proposal q before any speed benchmark. Do not copy reported maximum speedups. 
FP8-first on Ada stays; native NVFP4 requires suitable hardware, simulated low-bit or post-training INT4 storage not native FP4 training. Train vs inference format separate, qualify Q8/Q4 weight store, row scales and KV/state quantization independently. Muon partition and finite guards retained, tune LR/batch/decay with equal budgets and matched BF16/FP8 x AdamW/Muon; synthetic 35-step one-seed observations no superiority. 
## Gates and work sequence
1. Complete existing T0017/T0018, no task edits or new budget. Keep exact pilot checkpoint and source identity.
2. Review this design proposal and #86/#87 before any v0.3 code; Mac may work on small causal memory/provider/trace correctness in separate reviewed tasks; Linux profile and exact optimization, actual route/draft trace on checkpoint. No new tasks launched by this document.
3. Define a bounded data/token budget using actual pilot throughput, multiple seeds and independent train/validation families; fixed vocabulary, token-weighted NLL/bits per byte; measure label coverage, not raw steps. First feasibility ablations on Nano, e.g. 1–5M *unique* train tokens as planning target after data availability and resource measurement, not statistically adequate by itself; conditional memory capacity needs more coverage. Compare iso-parameters and iso-compute in separate matched regimes, quality/latency/bytes/energy Pareto, repeated measurements and paired uncertainty. Holdout/test only when frozen. No extrapolation from 64 steps.
4. Gate before Mini or heavy pretraining: matched reference and candidates, stable depth gain (or select smaller depth), measured profiling/resource fit, exact paging and cache semantics, useful MTP acceptance and net speed or negative evidence, credible table allocation vs MoE, training budget and source provenance. If not enough evidence, freeze stable baseline only, retain candidates as experiments.
5. Novelty claim withheld: conditional memory, looped experts, attention untying, expert streaming, depth speculation are published. Differentiator to investigate is their joint co-design for **measured quality per resident byte and committed token per second/joule on a single consumer machine under explicit tier budgets**, especially interaction of deterministic memory lookup, recurrent routing diversity and exact speculative verification. Compare established systems, not invented competitors. No public weights or production promises.
