# RFC 0005 addendum — native MTP decision and falsification protocol
Draft v0.2 | Issue #2 | 2026-11-26 | [PL](decision-v0.2.pl.md)
Depends on #3–#5. Supersedes only the provisional sequencing of RFC 0005; not an accepted RFC.

## 1. Common readout and objectives
Define h_r(t) as output of logical core pass r for prefix x_1:t. Let g(h) be a shared coda + final normalization + tied embedding projection E^T. The final target p_R is softmax(g(h_R)). Shallow p_r uses the same coda, executed for the selected readout. Coda attention state is separately keyed per readout depth; alternatively test a cheap tokenwise norm/projector readout with a distinct parameter and quality accounting. Do not silently share coda caches. Full-depth target stays fixed during speculative inference.

For a valid document position t, CE_r,k = -log softmax(H_r,k(h_r(t)))[x_(t+k)], where k=1 is NTP. H_r,1 = g for the shared-coda variant; H_r,2 can be a lightweight learned projection followed by E^T, initially independent of intermediate ground truth. Masks m_t,k exclude padding and document-crossing labels. Reduce each depth/offset by its own valid token count; zero valid entries contribute zero. The base loss L_final=CE_R,1. Compare:
- A0: final NTP only.
- A1: final NTP + lambda_d * mean_{r<R}(CE_r,1).
- A2: A1 + lambda_m * mean_{r in D}(CE_r,2), D initially {1,R}; horizon K=2 (next + one additional token).
- A3: A1 + lambda_a * mean_{r=2..R,t}(1-cos(P_r h_r(t), stopgrad(E[x_(t+r)]))), with same-document masking. P_r identity initially; learned projection separate. This is inspired by LoopMTP but retains SPLOT sandwich; no claim of faithful reproduction.
- A4: A2 + A3 (only if individual gains justify compute).
- A5: sequential conditioned MTP auxiliary baseline (teacher-forced predecessor in auxiliary path only; sampled-token conditioning at inference).

Set lambda_d=0.25, lambda_m=0.25, lambda_a=0.1 as provisional pilot values, sweep matched tuning budget and pre-register before training. All-depth training need not materialize all vocab logits at once; profile chunked/fused CE or checkpoint/recompute. For B=1,T=2048,V=32768 one BF16 logits tensor is 128 MiB, not counting softmax, gradients or buffers; multiple depths/offsets multiply this pressure. Report actual peak allocated/reserved memory and elapsed training. Same corpus, seeds, model/optimizer tuning budget; compare at both matched tokens and training compute. Validate gradient flow, masks, future-token perturbation invariance, zero-loss edge cases.

## 2. Draft strategies (fixed R per sequence)
D0: full-depth autoregression (target oracle).
D1: serial autoregressive shallow proposer at r_d=1, optionally r_d=2 if R>2; each proposal conditioned on actual proposed prefix. D1 requires its own coda cache or separate readout. Verify all proposals with full-depth target in one reference causal suffix forward if supported.
D2: parallel offset logits from A2, independent given prefix; define q_i as the actual sampled marginal conditioned only on committed prefix, valid as a conditional proposal that ignores earlier draft tokens. Use exact sequential verifier; do not treat top-k search/tree probabilities as q_i. Greedy first, stochastic after tests.
D3: Floodgates-inspired mask slots; learn draft-only adapter (frozen target first), prefix from verified final logical pass, no true future tokens. Compare shallow prefix vs deep prefix and train both under same budget. For GQA, read committed prefix K/V with logical depth selected explicitly; for GDN, clone appropriate verified state and adapt projection/update; never overwrite target state. Deep GDN state may be incompatible with shallow computations without adaptation, especially convolution history and normalization; test or fall back to same-pass. Mask slot attention and token positions must not leak future labels; draft and target are separate causal functions. Train using committed-prefix snapshots only, not future GDN states. Start k=2 then 4/8 if evidence warrants. D3 may require recomputation or chunked prefix snapshots during training; account for memory.
D4: pipelined/tree methods only after exact sequential suffix reference; state branches require independent snapshots (not just attention masks).

## 3. Exact verifier transaction
Given committed prefix, for each logical pass retain target cache/state S_R(prefix); draft uses separate scratch state. For sampled proposal y_i ~ q_i(.|prefix,y_<i), evaluate p_i from unchanged full-depth target with same sampling transforms (temperature/top-k/top-p etc.). Accept with min(1,p_i(y_i)/q_i(y_i)); on first rejection sample normalized max(p_i-q_i,0), commit accepted prefix plus correction, discard remaining draft. On all accepted, sample bonus from next target conditional. For greedy, accept only exact argmax under consistent tie policy, replace first mismatch with target argmax; bonus optional consistent with baseline. q_i must be the actual proposal distribution; q_i(y_i)>0. Implement residual normalization stably and test q=p, disjoint support and zero residual. EOS/stop/max token budgets terminate without bonus when appropriate.

Reference transaction recomputes the committed prefix from scratch on rejection and compares cache tensors/logits. Optimized strategy stores target state after each candidate position or replays accepted suffix from pre-verify snapshot. GQA KV truncation by logical pass; GDN matrix and convolution-history restoration; coda cache by readout; MoE routing scratch not committed; RNG policy recorded. Verify corrected token exactly once. Never commit a state computed on an unaccepted suffix. For stochastic testing compare distributions, not RNG-identical strings. No beam/tree verification claims until branch isolation tested.

## 4. Performance model and pass/fail criteria
Expected emitted tokens for K drafts with bonus and no EOS: 1 + sum_{i=1..K} P(all first i accepted). Estimate empirically; conditional acceptance can vary by position. Speedup = (mean emitted tokens * measured baseline time/token) / mean total round time. Include draft, target verification, cache restore, synchronization and transfer. Use actual wall-clock and CUDA events as separate metrics; synchronize before timing, warmup, record batch and context, quantization and decoding settings. For R=4, logical block counts per full token are 20, shallow r=1 costs 8 if shared coda used (not 25% of full). Hence two shallow serial drafts may already cost most of one full pass; parallel and bandwidth effects need measurement. For R=2, counts 12 vs 8. Do not assume 7.5x.

Pilot Nano/Mini, fixed R={2,4}, K={2,4}, contexts 512/2048, batches 1/4 when memory permits, >=3 training seeds for principal comparisons if budget permits, fixed held-out prompts and reported confidence intervals. Pre-register practical thresholds before full runs: candidate only advances when causal and exactness tests pass, full-depth loss/quality within agreed tolerance, net decode speedup >1.10 on a predeclared RTX 4090 workload with uncertainty reported, and no hidden memory-budget violation. The 10% threshold is a proposed engineering criterion, not a literature result. Report negative findings. Compare against optimized non-speculative and simple shallow proposer, separate wall time and train FLOPs; use compute-matched quality comparisons. Keep routing locality and low precision out of first MTP experiment to avoid confounds.

## 5. Implementation order
Implement dense baseline (#9), fixed recurrence and cache semantics (#4), common readout and objectives A0/A1/A2 (#2), D1 reference verifier, hybrid GDN with rollback (#5), then D2/D3 and optional A3/A5/A4. MoE interactions and optimized kernels follow. MTP is a first-generation feature, not an afterthought, but do not require unvalidated masked drafting for first correctness milestone.
