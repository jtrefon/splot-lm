# RFC 0004 — Expert locality with recurrent diversity and exact verification
Draft v0.1 | #6 | 2026-11-26 | [PL](pl.md)

## Hypothesis and alternatives
H5 refined: can a residency policy exploit causal routing hints across logical passes and draft/verify phases without altering the target distribution, and can bounded locality training improve the quality/transfer frontier without reducing useful depth? No novelty claim: DuoMI, LOOM, ReMoE, SP-MoE, CCAMoE and related work overlap; see [review](../../literature/reviews/expert-locality/en.md).

## Reference router
For physical block b, pass r, position t, logits a=W_b h, p=softmax(a) in FP32, S=TopK(p,k=2), weights w_e=p_e/sum_(j in S)p_j, y=shared(h)+sum_(e in S)w_e FFN_(b,e)(h). Eight routed experts plus one shared; tie deterministically, no dropped tokens in reference. Global balance over valid tokens: E*sum_e f_e mean(p_e), f_e=hard assignments/(k*N), report separately by pass and domain. Shared experts excluded from routed count. Compare shared router vs depth-conditioned small bias vs independent per-pass router at disclosed parameter budget. Exact counts in #3.

## Two independent locality axes
Time overlap: |S_(b,r,t) intersect S_(b,r,t-1)|/k. Depth overlap: |S_(b,r,t) intersect S_(b,r-1,t)|/k. Only compare within same physical pool and same document. Unrelated token random expected overlap k/E=0.25 for E=8,k=2 under uniform independent choices; empirical marginals may differ. Uniform chance is not the only control. Measure per-pass route entropy, load, dead experts, cross-domain distribution, hidden-state change, incremental NTP quality and loop benefit. Avoid maximizing reuse blindly: LOOM/DuoMI suggest diversity matters.

## Cache-only phase (exact target)
Key immutable weights by (checkpoint, physical block b, expert e, format); no pass ID for shared expert weights. Keep nonexpert/shared weights resident if budget permits, cache routed experts by bytes, record packed metadata/alignment. Target always executes original top-k weights, loading misses synchronously if needed; asynchronous prefetch only changes schedule. Verify identical target logits within numeric tolerance and greedy outputs; no claim bitwise identity across kernels. Speculative draft uses separate activation state; reject/rollback all target KV/GDN/coda state per RFC 0005, but may retain loaded immutable weights. Record pollution from discarded drafts. Never evict in-flight buffers; synchronize before reuse.

Policies P0 all resident (upper bound, different budget), P1 static frequency pins fit on training traces only, P2 LRU, P3 LFU, P4 causal cross-pass/draft hints, P5 future-aware offline oracle (not deployable). P4 ranks candidate expert by estimated next-use probability times miss cost minus eviction/transfer cost; no future token access. First use deterministic causal history; later lightweight predictor trained on held-out-separated traces. Prefetch budget bytes/time cap; track useful vs unused bytes, misses despite prefetch, cache occupancy, copy/compute overlap and deadline. Use same checkpoint, same routes, same byte budget for P1–P4; compare actual output unchanged. Oracle with equal-size experts can use Belady, unequal bytes need separate bound.

## Training phase (different target checkpoint)
Only after measuring baseline routes. Candidate distance d=1-sum_e min(p_(r,e),p_(r-1,e)); this soft total variation proxy is not actual TopK overlap or bytes. Instead of minimize-to-zero, use L_band=relu(d_min-d)^2+relu(d-d_max)^2. Set band using measured validation-free training traces, sweep, compare direct minimization and no locality loss plus DuoMI-inspired reference after full method review. Time-axis penalty separately, not conflated with depth. Compare shared vs per-loop routers with residual stability controls (RFC 0002). Add lambda*L_band to NTP/MTP/balance. No target cache-aware rerouting in exact phase; training changes model and demands quality checks. Test independent effects and interaction with MTP, not everything simultaneously.

## Trace schema and experimental gates
Trace row: schema version, checkpoint hash, run ID, request pseudonym, phase (prefill/draft/verify), committed prefix length, token position, logical pass, physical block, top-k IDs, weights, bytes per expert, actual execution order, hit/miss, load/evict/prefetch timestamps, accepted/rejected status, elapsed/transfer bytes. Avoid logging raw text by default. Batch and concurrency order must be recorded; training layer-major traces do not equal decode token-major traces. Replay actual chronological accesses. Record hardware, PCIe link, CPU/RAM, kernel, dtype, context, batch, cache budget, warm/cold starts. Report per-domain EN/PL, code/math; no hidden test selection.

Ablations: R=1/2/4 fixed; router shared vs pass-conditioned vs per-pass; NTP vs MTP after correctness; cache capacities 2/4/6 of 8 per equal-size pool or equivalent global byte budget, plus all resident. Separate simulation, forced offload and genuine memory-constrained model. Primary paired comparisons: P4 vs P2 at fixed checkpoint/routes; band training vs no locality at matched tokens and compute; P4 with/without draft hints vs non-spec and exact shallow baseline. Report 3 seeds where feasible, repeated timing trials, confidence intervals, full PPL and downstream task quality, expert diversity and depth improvement. Proposed thresholds for preregistration: >10% measured reduction in transferred bytes AND >10% net decode speedup in a declared constrained workload for cache-only candidate (target equivalent); trained locality must additionally stay within <=1% relative PPL loss and predeclared downstream/depth tolerances; revise only before observing confirmatory data. Cache hit gain alone fails. Do not assert speedup from simulated traces; include overhead, false prefetch, rollback and tail latency. Stop if data/compute insufficient.
